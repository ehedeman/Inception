Docker compose file: tells Docker how to build everything,
        so how multiple containers should be set up and run
        ->important to make containers interact ig

Dockerfile: contains instructions for how the images should be built
            ->also the dependancies

->Docker compose runs multiple containers, Dockerfile runs one images

->Dockerfile is plain text
->Docker compose is YAML

Dockerfile:

FROM: specifies the base image to use -> provides foundational layers

RUN: executes command in terminal of container (e.g install library)

CMD: specify default command that should run when container is started from image

Docker compose:

services: key for defining services that make up application

volumes: key for define persistent storage for application
        -> volume (piece of storage that is attached to a container)
        -> MariaDB database in this case i believe is supposed to be
            in a volume like that
        (Data persists even when container is stopped/removed)

networks: key for defining networks that containers should be connected to
-> virtual network that is used to connect them and allows them to communicate


docker volume: persistent storage location used to store data from a container

 ->bind mount: existing file/directory on host machine thats mounted to container

->named volume: managed volume created and managed by Docker.
stored in a specific location on host and not tied to a specific file or directory
useful for storing data that needs to be shared between containers since it can be easily
attached and detached to and from containers

->command: docker volume create [name]

(docker run -v [name]:/var/lib/mysql mysql ->as example of hpw to run mysql image and mount
the volume at /var/lib/mysql to the container.)

->volumes can be created and managed in the docker compose file as well

-> device is the actual volume, 'o' tells the system to bind it to the container 
(var/www/html is the working directory for that afterwards)
